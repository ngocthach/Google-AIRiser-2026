01 · Method
The experiment

One variable: the prompt

Prompt A — the polite one

990 characters

Feature list, a palette written as prose, and "return complete, runnable code with zero placeholders." The kind of prompt everybody writes.

Prompt B — the hardened one

3,880 characters

Same feature list, plus a runtime target, a scope fence, a token-consumption rule, an accessibility contract, and a self-check.

Both asked for exactly one thing: Layer 1 of PistonCraft — a header, a blueprint board with seven empty slots, and an inventory tray. No audio. No physics. No dyno.

Honest caveat: this ran through a Gemini CLI, not the AI Studio Build UI. That affects one finding — the file-shape result — and I flag it where it lands. The other six are properties of the prompt and travel anywhere.

02 · The defects
Defect 1 — the big one

A palette is not a design system

Prompt A said

A list of colours

[THEME & PALETTE]
- Background: #0B0F17 | Panels: #161F2E
  | Blueprint: #00F0FF | Steel: #94A3B8

Result: 221 raw hex codes sprayed through the components. Zero variables. Change the accent and you are editing 221 places.

Prompt B added

How they must be consumed

- tokens in :root in index.css,
  registered in the Tailwind theme so
  every utility resolves to a token
- no raw hex in any component file
- no arbitrary values: no bg-[#00F0FF]

Result: 24 tokens, hex only in :root, and a real theme config.

The rule: tokens without a consumption mechanism are decoration. The clause that does the work is "registered in the Tailwind theme" plus an explicit ban.

02 · The defects
Defect 2 — the method killer

It built all four layers at once

Asked for: a header, a static blueprint board, an inventory tray. Delivered: all of that, plus Web Audio synthesis, four-stroke piston kinematics, a Diagnostic Lab, a Dyno Chamber, an Otto-cycle P–V diagram and live horsepower curves — in the first message.

Why it happens

  • "Complete, runnable, zero placeholders" reads as build everything
  • Naming the Lab and Dyno tabs invited it to fill them
  • The prompt never once used the word not

Why it is expensive

  • Layer 2 is now an edit to bad code, not a clean addition
  • You cannot review 1,875 lines, so you accept it unread
  • Every later prompt rewrites features you never approved

Layering is not free. "Build layer 1" is a hope. A scope fence is a mechanism.

03 · The fixes
Fix 2 — anatomy of a scope fence

Three sentences that hold a layer

=== SCOPE FENCE - READ THIS TWICE ===
Layer 1 is the shell and the blueprint board. Nothing moves yet.

// 1. NAME THE FORBIDDEN FEATURES, ONE BY ONE
DO NOT build, and do not stub in passing: drag and drop, snapping,
sequence rules, minigames, the Diagnostic Lab, the Dyno Chamber, RPM,
horsepower, Web Audio, canvas animation, particles, or any Gemini call.

// 2. SAY WHAT THE EMPTY THING RENDERS INSTEAD
The Diagnostic Lab and Dyno Chamber tabs must render one centred panel
reading "Unlocks in the next build step." That is the whole feature.

// 3. GIVE IT A TRIPWIRE IT CAN CHECK ITSELF AGAINST
If you find yourself writing an oscillator or a requestAnimationFrame
loop, you have left Layer 1. Stop and delete it.

Part 2 is the one people skip. A tab with nothing behind it is an invitation. Give the model something boring and specific to build there and it stops improvising.

02 · The defects
Defect 3 — the shape of the project

One HTML file, five CDN requests

Prompt A produced

One index.html pulling React, ReactDOM, Babel standalone, Tailwind and Google Fonts from CDNs — transpiling JSX in the browser at runtime.

  • Dies with no network
  • Slow first paint, every load
  • Not what you would deploy

Prompt B produced

17 files — a real module project: components, types, data, a Tailwind config, an entry point. Imports, not script tags.

  • Runs with the network off
  • Each file small enough to review
  • Layer 2 has somewhere to go

Caveat, stated plainly: AI Studio Build already tends toward a multi-file project, so this gap is narrower there than in my CLI test. Keep the clause anyway — it costs three lines and it forbids the CDN fallback everywhere.

The type floor

"Smallest permitted font size is 14px. This is a game for children; 10px and 11px labels are a defect, not a style choice." Give the rule and the reason — the reason is what makes it stick.

The a11y contract

Put it under a heading that says part of the definition of done. Name the keys: Tab reaches, Enter and Space activate, a visible focus ring. "Make it accessible" produces nothing.

03 · The fixes
Fix — make it grade itself

The self-check clause

=== BEFORE YOU ANSWER, CHECK YOURSELF ===
1. Zero CDN script tags, zero external fonts, zero network requests.
2. Zero raw hex outside index.css.
3. Zero arbitrary Tailwind values in any component.
4. No font below 14px.
5. No audio, no animation loop, no minigame, no dyno anywhere.
6. Every button reachable and activatable by keyboard.
7. Layout holds at 1280x720 and at 390x844 without clipping.
State each of the 7 as PASS or FAIL, then list the files you created.

It returned 7 PASS. I independently verified checks 1 through 5 by grepping the output — they were true.

And here is the limit. Checks 6 and 7 — keyboard operation and responsive layout — cannot be verified by grep, and the model has no browser. Those two are a claim, not a result. Open the app and press Tab. A self-check makes a model careful; it does not make it right.

04 · Reuse
When it still goes wrong

Repair by naming the violated rule

It built too much

Scope creep

"You built features from a later layer. Remove the audio, animation and dyno entirely and restore the placeholder panel. This layer is the shell only."

It looks generated

Tokens ignored

"Raw hex appears in components. Re-read DESIGN.md, move every colour to a token, and list each replacement you made."

It rewrote working code

Collateral damage

"You changed files this layer should not touch. Revert them and apply your change only to the files listed in the brief."

It claimed PASS falsely

Unverifiable check

"Self-check 6 says PASS but Tab does not reach the inventory cards. Re-run that check honestly and fix what fails."

"It looks bad" gets you a different bad. "DESIGN.md forbids arbitrary values and line 40 has text-[10px]" gets you a fix.

05 · Method
Do not trust my numbers

Run the experiment yourself

# 1. Two prompts, same feature, same model, back to back
omp -p --no-tools "$(cat prompt-a.txt)" > out-a.md
omp -p --no-tools "$(cat prompt-b.txt)" > out-b.md

# 2. Count the defects instead of forming an impression
for f in out-a.md out-b.md; do
  echo "== $f"
  echo -n "css vars:  "; grep -cE '^\s*--[a-z0-9-]+\s*:'        $f
  echo -n "raw hex:   "; grep -oE '#[0-9A-Fa-f]{6}'             $f | wc -l
  echo -n "arbitrary: "; grep -oE '(text|bg|shadow)-\[[^]]*\]'  $f | wc -l
  echo -n "tiny type: "; grep -oE 'text-\[(9|10|11|12|13)px\]|text-xs' $f | wc -l
  echo -n "a11y:      "; grep -oE 'aria-[a-z]+|role=|tabIndex'  $f | wc -l
  echo -n "cdn:       "; grep -oE 'https?://[^"]+' $f | grep -v w3.org | sort -u | wc -l
done

Models move. These numbers are one model on one day. The seven blocks are the durable part; re-measure before you quote the table.

05 · Method
The limits

What forty lines cannot buy you

A hardened prompt reliably fixes

  • Colour and spacing consistency
  • Readable type and reachable targets
  • Keyboard access existing at all
  • Scope, so layers stay layers
  • Dependencies that survive no wifi

It does nothing at all for

  • Whether the game is fun
  • Whether the snap feels satisfying
  • Whether a child learns anything
  • Whether the idea is worth building
  • Whether the pacing works on a real kid

Tokens buy consistency. They do not buy taste. The prompt-B app is well-built. Whether it is a good game is a question you answer by handing a tablet to a nine-year-old and watching their face — not by writing a better prompt.

Six minutes, seven blocks

Spend the words on what it must not do.

The features you want are the part you already write well. Every measurable gain here came from the runtime target, the scope fence, the consumption rule and the self-check — the four blocks almost nobody writes.
