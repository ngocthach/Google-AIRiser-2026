# 45-minute talk deck: build a kids English + inventions game with the MVP pipeline

## Overview

Create `docs/slides/kids-invention-game-pipeline-slides.html` — a second self-contained deck reusing the shell, CSS tokens and copy-button JS of `docs/slides/mvp-pipeline-prompting-slides.html`, but retargeted.

**Confirmed decisions (from the user, 2026-08-15):**

| Decision | Choice |
|---|---|
| Format | **Talk only.** No hands-on blocks. 39 slides, ~46 min — see the timing table. |
| Pipeline framing | **The pipeline discovers the game.** Start from a broad problem; the game is the *chosen* idea at Stage 02. |
| Language | **All English**, including presenter notes. |
| Game MVP | **Fix the Machine** — real-time, English words are the controls. Firestore stores unlocks + best streak. *(Revised 2026-08-15, see below.)* |

A talk-only, all-English, different-example deck is a different artifact. Sharing the file would mean branching content in-place. Copy the shell, replace the content.

## Revision — 2026-08-15, after the deck was built

The first build used **invention cards + a word-match quiz**. On review the user's verdict was correct and the deck's own design system had already predicted it: the anti-feel says *"must NOT feel like a worksheet"*, and a word-match is a worksheet. The loop had no fail state, no real-time pressure, no skill, and nothing to do with a finished collection.

An intermediate proposal — Little Alchemy style combining of collected inventions — was also rejected. It fixes "the collection has no use" but is a discovery **toy**, not a game: still no stakes, no dexterity, nothing happening in real time.

**The product is now a real-time action game.** The root change: English stopped being the *content* and became the *control scheme*. A child who cannot read the label cannot play. Everything below describes the current product.

## The running example — the spine of every worked slide

**Spark — Fix the Machine.** A steam engine runs and comes apart. Six parts, each labelled with one English noun. Every 2-4 seconds a part faults, a banner reads **"THE VALVE IS LOOSE!"**, and the child has **three seconds** to tap that part. Miss, and a pressure gauge fills. Fill the gauge and the machine explodes, sootily, and restarts in one tap with no score screen. Survive 60 seconds and the real invention is revealed with three sentences on why it mattered — optional reading, with a play-again button always visible. Faults come faster as the streak grows; after streak 10, two at once.

- **Screens (3):** Sign in (Google — a *parent* action) · The Workshop (which machines are fixed, which are locked, best streak) · The Machine (the round itself).
- **Stack:** React (TS) + Tailwind with all values as CSS custom properties · Firebase Auth (Google) + Cloud Firestore · `@google/genai`, current Flash model, key in AI Studio's server-side secret.
- **Budget:** 60 hours solo; plan sums 59h across 10 tasks.
- **Data model:** `users/{uid}` (displayName, ageBand, wordLevel) · `users/{uid}/machines/{machineId}` (fixed, bestStreak, partsSeen[]) · `machines/{id}` seeded read-only (name, year, parts[], faults[], blurb).
- **Deliberately not built:** no leaderboard, no audio/TTS, no multi-child accounts, no offline mode.

**The Research stage must earn the age band.** Just as the original deck's Ươm Mầm prompt argued against "ages 6-22", this deck's Research prompt argues against "kids" as one audience and lands on 8-11, and asks *who has to say yes* — the answer is the parent, which is why Sign in is a parent screen and not a kid screen. That is the pipeline visibly changing the product, which is the deck's whole thesis.

## Revision 2 — 2026-08-15, budget and filled prompts

**Budget raised 20h → 60h.** The task table was rebuilt rather than scaled: 10 tasks summing to 59h, with the parent progress screen (6h) cut to fit. The extra 40 hours went to a real difficulty curve, four machines instead of one, a proper Workshop screen, vocabulary tiers regenerated by the model, and the states/accessibility work that a timed game needs. The 60h figure now appears in the Research context, the converge scoring criterion, and the Plan prompt's cut rule.

**Every template prompt now has a filled-in twin.** The problem: in a *talk*, an attendee cannot run stage 3's prompt because it says "paste the output of stage 2" and they have not run stage 2. They would have to sit and wait on Gemini. So each template slide is now followed by a runnable one with the previous stage's artifact already pasted in, copy button labelled **COPY — RUNS NOW**. Slide 8 was the existing model for this; slides 12, 16 and 25 are new.

Stages whose `data-full` was already fully filled (Design system, Build L1, L2+L3, Rules, AI layer, Test, Eval) did not need a new slide — their COPY FULL is already runnable.

**One ordering bug fixed on the way:** the screens prompt said *"using ONLY the tokens above"* while the token artifact came **after** it. The token slide now precedes the screens prompt.

**The killer assumption changed with the product, and got sharper.** It was "a child abandons a card they cannot read." It is now **"a slow reader loses every round in eight seconds — the timer turns reading speed into the difficulty."** That is a genuine design risk of a timed reading game, it is named on slide 13, and it reappears as a test case on slide 34.

## The four beats that earn this deck's existence

The original deck's example (one screen, seeded data, no login, no database) cannot teach these. This one must:

1. **Firestore security rules.** A kids' app with children's progress data, on a database that defaults to open or expiring test mode. One prompt locks it to `request.auth.uid == userId`. Plus Decree 13/2023/ND-CP: under-16 data in Vietnam needs verified parental consent — which is *why* the parent signs in, and what to say when a judge asks.
2. **Cache the AI output — and the game removes the excuse.** Generate the parts, faults and win text once, store in Firestore, serve from there. In the card version this was an argument about cost. In a real-time game it is arithmetic: **a round is 60 seconds of real time and a three-second fault timer cannot wait on a two-second API call.** Same lesson, no longer arguable.
3. **Do not use the book's images.** The DK *1000 Inventions & Discoveries* artwork is copyrighted. Generate the machine and its six parts (AI Studio's Build agent generates images on demand) or use public-domain sources. It is the kind of thing that disqualifies a submission after it has won.
4. **Two kinds of failure.** A game needs a fail state; a learner does not need to be told they failed. Losing a round must be funny and restart in one tap. Getting a word wrong is never commented on — no red on the label, no WRONG, no report card; the gauge rising is the world reacting, not the app judging. **The original design system collapsed these into one rule** ("no red, no buzzer, no timer") and would have made the game unbuildable. Separating them is now slide 22's whole point.

## Carried forward from the 2026-08-15 audit (non-negotiable)

The sibling deck was just fixed for producing bad CSS. This deck inherits the fixes or it regresses:

- The **DESIGN.md workflow** — design stage outputs a DESIGN.md, the agent re-reads it before every change.
- The **token-consumption block** — `:root` in `index.css` + registered in the Tailwind theme, no raw hex, no arbitrary values.
- The **"tokens buy consistency, not taste"** slide.
- The **design QA prompt** — screenshot back into Gemini, audit against DESIGN.md.
- **Layer order** — tokens in the first build message, never "pretty later".
- **No hardcoded model names**; deploy flow flagged as needing live verification.

Added by the game pivot, and specific to a timed game for children:

- **Accessibility became a mechanic, not a checklist.** A fault is never signalled by colour alone — the banner names the part in words and the part moves, so a red-green colour-blind child can play at full speed. A whole round must be completable on a keyboard. The design QA prompt (slide 32) now includes *"convert the screenshot to greyscale — can you still tell which part is faulting?"*
- **56px targets and 18px labels stopped being cosmetic.** In a three-second decision they are the difficulty setting.
